# 密码学 RAG 开发集评测报告

运行日期：2026-07-27

## 1. 评测范围

- 语料：44 篇 NIST/FIPS/SP 与 RFC 官方文档；
- 切分方式：按章节/页码进行结构化切分；
- 切分参数：`chunk_size=1200`，`chunk_overlap=120`；
- Chunk 总数：6,073；
- 评测集：100 条开发题；
- 可回答 / 不可回答：90 / 10；
- 检索截断：`top_k=10`；
- 基础检索器：BM25；
- Agent 融合：每个子查询召回 40 个候选，再使用 Reciprocal Rank Fusion（RRF）融合。

问题类型分布：

| 问题类型 | 数量 |
|---|---:|
| 主张核验（claim verification） | 16 |
| 定义题（definition） | 14 |
| 多跳题（multi-hop） | 23 |
| 参数比较（parameter comparison） | 32 |
| 版本路由（version routing） | 5 |
| 不可回答（unanswerable） | 10 |

全部题目均通过以下检查：

- manifest 来源校验；
- 真实解析后的章节校验；
- gold evidence 校验；
- `query_id` 唯一性校验；
- `review_status=verified` 状态校验。

## 2. 检索结果

检索指标在 source level 计算。同一来源返回多个 chunk 时只计为一个相关来源。

不可回答题没有 qrels，因此单独统计为 `unjudged_queries`，不进入 90 条可回答题的检索指标分母。

| 方法 | Hit@10 | Recall@10 | MRR@10 | nDCG@10 | 平均延迟 |
|---|---:|---:|---:|---:|---:|
| BM25 | 0.9667 | 0.9611 | 0.8588 | 0.8821 | 5.71 ms |
| Agent + BM25 | 1.0000 | 1.0000 | 0.9778 | 0.9802 | 23.22 ms |
| 绝对提升 | +0.0333 | +0.0389 | +0.1190 | +0.0981 | +17.51 ms |

Agent 按问题类型分组的结果：

| 问题类型 | Hit@10 | Recall@10 | MRR@10 | nDCG@10 |
|---|---:|---:|---:|---:|
| 主张核验 | 1.0000 | 1.0000 | 0.9688 | 0.9769 |
| 定义题 | 1.0000 | 1.0000 | 1.0000 | 1.0000 |
| 多跳题 | 1.0000 | 1.0000 | 0.9565 | 0.9579 |
| 参数比较 | 1.0000 | 1.0000 | 1.0000 | 1.0000 |
| 版本路由 | 1.0000 | 1.0000 | 0.9000 | 0.9101 |

本地实验中，Agent 的平均延迟约为 BM25 的 4.1 倍。绝对延迟仍较低，是因为基础检索器为内存中的 BM25；如果改为 LLM 规划器或远程向量数据库，延迟与成本权衡会明显变化。

## 3. Agent 设计

当前 Agent 为确定性规则系统，不调用 LLM。每道题的查询计划都会序列化到评测记录中，便于复盘与消融。

处理步骤：

1. 识别问题中明确出现的 RFC、FIPS 和 SP 编号，包括 NIST 修订版与更新后缀；
2. 把复合问题拆成原问题、子句查询和来源定向查询；
3. 根据 manifest 的 `topics` 字段进行领域路由，覆盖 AES、Argon2、hash-to-curve、HKDF、ML-KEM、ML-DSA、SLH-DSA、OpenPGP、COSE 等主题；
4. 为路由到的来源补充“问题 + 文档编号 + 文档标题”查询；
5. 当问题明确要求“当前、最新或取代关系”时，根据 `supersedes` 与 `superseded_by` 降低旧版文档权重；
6. 对跨文档比较题，为每个明确指定或主题路由到的来源预留至少一个证据位置；
7. 使用 RRF 合并多路候选，并应用显式来源与主题路由加权。

这种设计的优点是行为可解释、可测试、可做逐项消融；缺点是需要持续维护领域术语和协议上下文规则。

## 4. 错误分析

### 4.1 BM25 基线的主要错误类型

BM25 的失败主要分为四类：

- 中英文语义错配：中文问题中的“安全强度”“清除余因子”等含义，无法稳定匹配英文文档中的 `security strength`、`clearing the cofactor`；
- 多跳来源覆盖不足：比较 HKDF 与 SP 800-108 时，只召回两个 gold source 中的一个；
- 版本路由不足：TLS 1.3 的旧版与替代 RFC 同时存在时，正确版本不一定排在前面；
- 同来源 chunk 挤占：词法高度相关的同一文档可能占据大部分 Top-K，挤掉比较题需要的另一个来源。

### 4.2 路由规则引入的回归

Agent 规则是在观察上述失败后加入的。迭代中发现并修复了两个典型回归：

- 把所有包含 `Argon2` 的问题都路由到 RFC 9106，会遮蔽 RFC 9580 中 OpenPGP 专用的 Argon2 S2K 定义；
- 把所有包含 `ChaCha20` 的问题都路由到 RFC 8439，会遮蔽 RFC 9053 中 COSE 专用的算法配置。

修复方式是增加协议上下文路由，同时融合“协议文档”和“底层密码原语文档”，让更具体的协议来源优先。

### 4.3 被否决的“默认旧版降权”实验

曾尝试对所有废止文档默认降权，结果如下：

| 变体 | Hit@10 | Recall@10 | MRR@10 | nDCG@10 |
|---|---:|---:|---:|---:|
| 默认降低旧版文档权重 | 0.9778 | 0.9667 | 0.8962 | 0.9044 |

该规则损害了需要核验旧 RFC 原始表述的问题。因此最终实现只在问题明确出现“当前、最新、取代”等版本意图时启用旧版降权。

这个负向结果说明：文档被新版本取代，不代表它在所有查询中都不相关。版本路由必须结合查询意图。

### 4.4 最终仍存在的排序问题

最终所有相关来源都进入 Top-10，但仍有 7 道题的 MRR 或 nDCG 小于 1：

- `pilot-014`：RSA 相关来源位于第 2 名；
- `pilot-015`：第二个 EdDSA 相关来源位于第 5 名；
- `crypto-041`：SP 800-57 位于第 2 名，前面是另一个安全强度相关文档；
- `crypto-044`：第二个 DRBG / 算法迁移来源位于第 3 名；
- `crypto-046`：替代后的 TLS RFC 首次出现在第 3 名；
- `crypto-066`：问题没有明确写“当前”，因此现行 TLS RFC 位于第 2 名；
- `crypto-085`：通用 AEAD 接口 RFC 位于第 2 名，前面是协议专用的 AEAD 段落。

这些属于排序质量问题，不是 Top-10 覆盖失败。项目保留了这些真实误差，没有继续增加过窄规则来强行制造满分排序。

## 5. 生成与拒答链路冒烟测试

配置：

- 检索器：BM25；
- `top_k=5`；
- 生成器：mock；
- 固定拒答阈值：`min_top_score=12.0`；
- 问题数：100。

| 指标 | 结果 |
|---|---:|
| 引用格式合法率 | 1.0000 |
| 引用来源精确率代理指标 | 0.7378 |
| 引用来源召回率代理指标 | 0.9302 |
| 拒答 Precision | 0.6364 |
| 拒答 Recall | 0.7000 |
| 拒答 F1 | 0.6667 |
| 假阳性 / 假阴性 | 4 / 3 |

这次 mock 运行证明以下工程链路能够覆盖全部 100 题：

- 题集加载；
- 检索；
- 拒答分支；
- 引用编号解析；
- 逐题结果写入；
- 分组指标汇总；
- 延迟记录；
- 实验结果序列化。

但它不能测量：

- Answer Correctness；
- 引文内容是否真正蕴含答案；
- Citation Completeness；
- Faithfulness。

这些字段目前没有人工或独立 judge 标签。拒答结果也表明，20 题先导集上选出的单一 BM25 原始分数阈值，无法可靠泛化到 100 题开发集。

## 6. 结果解读

可以得出的结论：

- 结构化元数据和查询路由能明显改善跨文档覆盖与排序；
- 新增 8 篇文档后，BM25 的 MRR 略有下降，说明语料扩容带来了真实干扰；
- Agent 在扩容后仍保持 1.0000 的 Hit@10 与 Recall@10；
- 确定性 Agent 能够提供可审计的查询计划和清晰的误差归因；
- 仅靠固定检索分数阈值不能实现可靠拒答。

不能得出的结论：

- 不能把开发集上的 1.0000 Hit/Recall 当成未见测试集泛化能力；
- 不能用引用格式合法率证明引用正确；
- 不能用来源级命中证明检索到了正确章节；
- 不能用 mock 生成结果证明最终答案正确或忠实。

## 8. 有效性限制

- 100 条题是开发集，Agent 迭代过程中查看过这些题的错误；
- `verified` 当前不代表已经完成独立的第二人复核；
- 语料仍以标准和规范为主，尚未覆盖论文中的定理、证明、公式图结构；
- source-level 相关性可能掩盖“来源正确但章节错误”，章节与 gold evidence 校验只能降低风险，不能完全消除；
- 当前 1.0000 Hit/Recall 不应包装成未见测试集成绩；
- 主题路由规则可能在新协议或术语重叠场景中产生新的误路由。

下一步最可信的实验方式是：

1. 冻结当前实现与全部路由规则；
2. 请独立复核者检查问题、答案、来源和证据；
3. 新建未参与调优的隐藏测试集；
4. 只在隐藏测试集上运行一次正式对照；
5. 对真实模型回答进行 Answer Correctness、Citation Correctness、Citation Completeness 和 Faithfulness 标注。
